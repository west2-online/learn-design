# 职业化初步：覆盖大部分职业的能力提升清单

> 版本：2026-08-24
> 用途：总结 `all/` 目录调研的全部岗位（01~07 簇，游戏美术除外）重叠的重点能力，并以**第一学期及寒假轮已经形成的能力**为基线，划定第二学期「对接真实岗位」仍需培养的公共能力范围。
> 方法：对 01~07 簇全部 JD 样本的高频要求做交叉编码，保留「跨簇出现、覆盖大部分职业」的能力，剔除单簇特色能力（如原画手绘、引擎特效、车载 HMI 专属规范）；再逐项对照 `steps/term1/` 与 `steps/winter/` 的学习、作业和面试要求，避免将已经完成的寒假轮基础重复安排为第二学期入门任务。
> 「覆盖」判定：该能力在 ≥3 个岗位簇的 JD 中出现，或在其所在簇内为近乎必选要求。

## 1. 通用底座深化

### 1.1 设计系统与组件化治理

- JD 证据：几乎每条 UI/交互/UX JD 要求「建立并维护设计规范/组件库」（武汉逸博晟、环境监测总站、上海昊沧、石家庄前端 UI）；视觉岗要求「设计体系搭建维护」（微派）；设计管理簇（06）以此为独立职能；字节飞书 DesignOps 为高阶形态。
- 第一学期已有：task4 的 Component System / Design System / Token。
- 寒假轮新增：task1 将 Token 落到真实博客主题与代码变量中；task2 将个人 VI Token 化并适配多个平台；task3 复用博客 Token / 组件建设作品集页面，已经经历一次「系统扩展而不是重新画一遍」。
- 第二学期提升：从个人单项目复用进入跨文件、跨项目、多人 Library 治理；完善 Primitive → Semantic → Component Token 与代码侧映射（Storybook 等）；处理组件/Token 的 Review、发布、更新、Deprecated、迁移与多品牌/多语言/多端 Mode。

### 1.2 跨端与平台规范

- JD 证据：UI/UX 岗普遍要求「Web+移动端多终端」（字节飞书、极致上下文、短剧行业全终端）；客户端岗要求 iOS/Android 双端规范（亮点信息、邮乐）；鸿蒙原生岗位已出现（珠海字符科技）；视觉岗要求跨平台多终端（腾讯校招）；HMI/硬件岗要求平台 Guidelines（07 簇）。
- 第一学期已有：task4 Responsive Layout（嵌套 Auto Layout、Hug/Fill/Fixed、Min/Max、多尺寸验证）。
- 寒假轮新增：task1 在真实内容下完成桌面/移动响应式、深浅色和浏览器验收；task2 针对设计社区与社交平台的尺寸、规则、受众分别落地个人品牌；task3 再次验证作品集长文在移动端与深浅色下的阅读体验。
- 第二学期提升：已有能力仍以 Web 与平台物料为主，继续系统学习 iOS Human Interface / Android Material / 鸿蒙 ArkUI / Windows / macOS 等原生 Guidelines；处理安全区、多输入方式、多分辨率、多语言、动态内容与商店物料，并建立跨端一致性验收清单。

### 1.3 无障碍设计（并入职业化初步）

- JD 证据：交互/UX 岗高频出现无障碍检查（百度交互、01 簇 UX 向要求）；独立岗位存在但少（高级交互-信息无障碍 25-35K·14薪）；腾讯×中国残联联合实验室为行业动向；政策与标准推动（标准院无障碍规范编制）。
- 第一学期已有：task4 中键盘操作、Focus、触控目标、色彩对比的基础检查。
- 寒假轮新增：task1 将文字与背景对比、字号、焦点可见性和「不只依靠颜色」落实到公开博客；task3 在长文、真实图片、移动端和深浅色环境中再次检查阅读体验。
- 第二学期提升：从视觉层基础检查进入 WCAG 2.x 核心准则与多障别设计（视觉/听觉/肢体/认知）；补齐语义结构、键盘完整路径、读屏、缩放与重排、动效减弱偏好；使用读屏与自动/人工检查工具完成可重复的无障碍验收。

### 1.4 动效与微交互

- JD 证据：UI/UX 岗普遍要求动效（顺丰校招「AE 动效或原型工具」、微蜜友「AE/Rive 关键动效」、猎头动效岗「UX 动效方法论」）；游戏 UI 岗要求动态 UI（米哈游实习）；运营/视觉岗要求 AE（02 簇）；Rive 成为新交付标准（掌登万民、杭州天桐）。
- 第一学期已有：task4 Prototyping（Smart Animate/Easing/Duration）。
- 寒假轮新增：没有独立的系统动效学习与可验收交付，不应把博客中零散的 hover / transition 当作岗位级动效能力。
- 第二学期提升：AE / Rive / Lottie 基础操作与交付流程；功能性动效与情感化动效方法论；动效规范（时长/缓动/层级）与开发侧还原跟进；动效与性能、Reduced Motion、不同设备输入反馈之间的平衡。

## 2. 研究与验证

### 2.1 用户研究与可用性测试

- JD 证据：交互/UX 岗要求用户画像、体验地图、用户反馈分析（01 簇）；产品岗要求用户需求挖掘与场景分析（大疆、鸿合）；用研岗为独立职业（小米、软通动力：问卷/访谈/焦点小组/共创）；游戏 UI 岗要求用户体验研究（IGG）。
- 第一学期已有：task4 的 UX 验证与迭代（真实任务测试、观察记录、修改与复测）。
- 寒假轮新增：博客、作品集与内容运营带来公开访问和自然反馈，但 winter/task4 主要验证内容选题与视觉模板，并未替代有研究问题、样本与任务脚本的系统用研。
- 第二学期提升：扩展问卷设计、深度访谈、焦点小组、用户共创等方法；规范可用性测试的研究问题、招募与样本、任务脚本、指标、观察记录、结论与复测；训练将研究结论转化为设计决策并形成可复查报告。

### 2.2 数据意识与设计验证

- JD 证据：交互岗要求「用户反馈及数据分析」（百度高级交互）；产品岗几乎全 JD 要求「数据分析/数据敏感度」（阿里、腾讯、大疆、字节）；UX 岗要求关注发布后数据（01 簇）；华为产品体验师要求 NPS 与舆情。
- 第一学期已有：仅有定性测试，未形成数据验证能力。
- 寒假轮新增：winter/task4 读取阅读量、互动、完读率等平台数据，结合评论、私信与朋友反馈调整选题和视觉模板；task1 可选接入访客统计与 SEO，已经形成「发布—观察—迭代」的初步意识。
- 第二学期提升：区分内容运营指标与产品体验指标；理解事件、埋点和数据口径，使用转化、留存、漏斗、任务成功率、NPS 等指标；建立 A/B 测试基本意识，在样本、变量与结论强度允许的范围内用数据复盘设计。

### 2.3 竞品与行业分析

- JD 证据：产品岗几乎全 JD 要求竞品分析（腾讯 VooV、大疆、UCloud、鸿合、蜀俊博凌）；交互/视觉岗要求竞品与行业设计分析（腾讯资深视觉）；策略岗以此为专职（威马前沿策略）。
- 第一学期已有：task1 作品分析、task2 参考案例分析。
- 寒假轮新增：task1 分析博客与技术方案，task2 调研设计社区/社交平台的 Context，task3 依据个人定位筛选案例，task4 分析同方向账号的选题、标题与封面；已经能够在具体交付前收集参考并说明取舍。
- 第二学期提升：从「寻找可借鉴案例」升级为结构化竞品拆解（定位/用户/任务/流程/视觉/技术/商业）；持续追踪行业与招聘市场变化；区分事实、推断与建议，形成带来源、方法、结论和局限的调研报告与演示。

## 3. 产品与业务

### 3.1 产品思维与需求管理

- JD 证据：产品簇（04）全 JD 核心要求（需求分析、PRD、优先级、推进落地）；UI/UX 岗高频要求「与产品经理协作拆解需求」（短剧行业、广州黄埔星数智）；游戏策划岗要求「从玩家体验出发」（4399）。
- 第一学期已有：task4 前期构思（Purpose/Audience/Context、需求拆解）。
- 寒假轮新增：task1 将博客作为长期内容产品，完成定位、IA、技术选型、实现、部署、维护与迁移取舍；task2 根据不同平台 Context 调整同一品牌系统；task4 为内容运营定义受众、目标、发布节奏和衡量方式。
- 第二学期提升：从个人产品的完整经历进入更正式的需求管理：用户问题与业务目标、需求池、用户故事、优先级与范围、版本规划、PRD / 原型表达；训练在体验、成本、周期、风险与业务指标间取舍，并跟进发布后的结果。

## 4. 技术与实现

### 4.1 代码与实现边界

- JD 证据：Web UI 岗要求「了解 HTML/CSS」（官网向岗高频）；网易交互校招偏好「了解前后端逻辑、API 原理」；游戏 UI 岗要求 Unity/UE 落地意识（莉莉丝动效「在 Unity 落地」、米哈游 UE5 项目）；设计工程簇（05）以代码为产出物；可视化岗要求 Three.js/ECharts（07）。
- 第一学期已有：task3 的 CSS 基础与主题设计、task4 的 Dev Mode 交付。
- 寒假轮新增：task1 理解 HTML / CSS / JS、Flex / Grid、响应式、状态、组件与 Token，并与 Agent 完成真实网站的实现、部署、维护和验收；task3 将 GAMES101 概念映射到 Three.js，完成可嵌入网页的 3D 组件。
- 第二学期提升：不再从「认识 HTML/CSS」起步，重点训练读代码、使用浏览器工具定位问题、修改样式/状态/响应式并判断实现复杂度；理解 React / Vue 的组件与状态、API / 数据 / 构建部署边界。Unity UGUI / UI Toolkit、Unreal UMG 等引擎能力只在对应目标岗位中继续深化。

### 4.2 AIGC 生产化与合规

- JD 证据：2025-2026 全簇新 JD 均加 AIGC 要求：腾讯校招视觉「熟练 AIGC 工具」、京东 AIGC 电商（ComfyUI/MJ/SD 硬性要求）、AIGC 设计师独立岗位井喷（咪咕、云图校招、山水原创关键词库）、AI 视觉（杭州全速）、AI 产品经理要求会用 Cursor/v0 等。
- 第一学期已有：task5 AI 融合工作流（Agent/MCP/Skill、两类 AI 设计工作流对比）。
- 寒假轮新增：task1 / task3 将 Agent 用于公开网站与 Three.js 组件，要求完整上下文、拆分任务、读懂关键代码、人工验收、记录 Prompt / 回复摘要 / 人工修改并检查授权；AI 从练习工具进入真实交付链路。
- 第二学期提升：在已形成的 Agent 协作基础上，按岗位补齐 MJ / SD / ComfyUI / Rive 等生成式工具链与 PS / PR 精修；管理模型、参数、提示词、参考资产、版本与可复现工作流；评估稳定性、一致性、编辑性、版权与隐私，并能清楚说明 AI 参与范围及自己的判断。

### 4.3 三维基础（3D/C4D/Blender）

- JD 证据：视觉/营销岗要求 C4D（TCL、品牌视觉岗）；三维视觉设计师为独立岗位（02/03 簇）；新兴簇（07）HMI 3D、数字孪生、XR 均以 3D 为底座；游戏 UI 岗部分要求引擎 3D 认知。
- 第一学期已有：审美积累中的立体设计观察，没有可验证的三维制作能力。
- 寒假轮新增：winter/task3 至少学习 GAMES101 的变换、光栅化与着色，理解 Camera / Material / Mesh / Geometry 等对应关系，并完成一个可嵌入博客或作品集的 Three.js 组件；Blender / Spline 仍为可选，不能视为已经完成建模管线。
- 第二学期提升：公共部分补齐 Blender 或 C4D 的建模—材质—灯光—渲染出图基础与三维/平面合成；Web / 数据可视化方向可深化 WebGL / Three.js，XR / HMI / 游戏方向再按目标 JD 进入交互、引擎、性能与资产规范。

## 5. 协作与职业化

### 5.1 真实协作与项目推进

- JD 证据：几乎所有 JD 要求「与产品、研发、运营跨职能协作」（01/02/03 簇高频；产品岗要求协调研发/设计/测试/算法推进落地）；游戏 UI 岗要求与策划/程序/主美协作。
- 第一学期已有：Git/PR 协作初步、task4 协作交付（Dev Mode/Handoff）。
- 寒假轮新增：task1 通过需求描述、Agent 实现、人工验收、Git、部署、维护、README 与迁移策略跑通个人项目闭环；task2 / task3 继续复用规则和资产，并用可访问链接、源文件和授权清单形成可交接证据。该经历仍以个人与 Agent 协作为主，不等同于真实跨职能团队协作。
- 第二学期提升：使用有真实委托方、产品/研发/运营角色和时间限制的项目，完成需求确认、范围与排期、方案评审、设计交付、实现跟进、效果验收、变更记录和复盘；考核沟通、冲突处理、责任边界与结果，而不只检查最终设计稿。

### 5.2 作品集与求职表达

- JD 证据：几乎所有设计岗要求作品集（米哈游「简历须附作品集链接」、北森「PDF 简历含作品集」、游戏 UI 岗要求手绘作品）；校招/实习岗位普遍「实习经验优先」；面试表述在 01/04 簇面经中反复强调。
- 第一学期已有：各 task 的过程记录与 README 交付习惯。
- 寒假轮新增：task1 / task2 建立个人博客、个人 VI 与跨平台公开入口；task3 筛选 3~5 个案例，按背景与问题、目标与角色、调研与思考、方案与过程、结果与验证、反思撰写 Case Study；task4 使用内容发布与反馈持续运营，并在寒假轮面试中展示与解释。

## 6. 使用说明
