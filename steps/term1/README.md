## 怎样阅读学习与作业

- `学习` 保留知识、工具、课程、案例与方法，供你理解和继续深入；不要求每个链接都看完、每款软件都使用、每个知识点都另交一份练习。
- `作业` 说明本次需要实际完成什么、留下什么证据。先通读，再用学习部分解决制作中遇到的问题；任务中明确的数量、核心能力与验证要求仍需完成。
- 同一项目可以同时证明多项能力，短说明可以合并到 README；文件数量、Page 数量和过程包装的复杂程度都不是考核目标。

## 前两轮的交付组织

### README、Figma 与项目文件

1. 每次提交以 README 为入口，写清本次任务、选题、范围、主要结论、阅读顺序、提交日期与版本。
2. README 链接到实际使用的设计文件、Prototype、报告、源码与线上成果；不用到的类型无需创建。例如 task1 不要求 Figma，winter/task3 不新建个人提交目录。
3. 文字说明可以直接写在 README，也可拆成 Markdown 文档再链接。报告讨论某个设计决定时，给对应的 Figma 节点链接或节点名；源码在独立仓库时，给本次 Commit / Tag 和具体文件入口。
4. Figma 的首个 Page 作为预览与导航入口，注明版本和 README 链接；其余内容按各 task 要求用 Pages / Sections 组织，不必为每个分区单建一页。正式稿、规范、组件、参考与过程各有可定位的位置即可。
5. 同一内容确定一份主版本：Figma 保留可编辑设计与交互，Markdown 保留长说明和记录，项目仓库保留源码与运行资产，博客保留公开文章。其他位置可以引用摘要、图片与链接，不必把全文或整个项目反复复制。

### 图片与大文件怎么提交

> [!IMPORTANT]
> 控制图片提交是为了避免 Git 仓库及其历史被大文件撑大，不是禁止预览图、截图或某一种文件格式。
> 体积合适、确实有助于阅读和复查的图片可以直接上传；按用途选择格式，先查看实际文件大小。

- 普通预览可裁切到所需区域、降低到实际阅读分辨率，或转为 WebP 等合适格式；本身很小的 PNG / JPEG 截图可以直接提交，无需为了格式再次转换。
- SVG、CSS、Markdown 等源文件通常适合版本管理，可按任务需要提交；SVG 若嵌入大图、含大量路径，也需检查实际体积，不能只凭扩展名判断。
- 同时检查单文件大小、附件总量和是否频繁重复导出。无需机械统一尺寸或压缩到看不清文字、细节、色彩差异；重要原始资产和生产文件应保留质量。
- 大幅高分辨率图、长录屏、视频、复杂 3D / 设计工程等按实际大小放在合适的资产存储、交付空间，或评估 Git LFS 后管理，README 提供可访问的源文件 / 交付链接。换一个普通 Git 仓库并不会自动解决大文件问题。
- 少量必要预览是阅读辅助，不替代任务明确要求的可编辑源文件、Prototype 或可运行成果。运行所需的轻量图片、字体、SVG 等仍应随项目维护，确认授权后使用。
- 各 task 的提交部分会分别说明哪些图片适合直接附上、哪些源文件与导出必需、哪些大文件宜提供外部链接。
