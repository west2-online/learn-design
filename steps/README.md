# 学习阶段

> 考核的目的从来都不是为了卡掉任何一个同学的转正机会，而仅是对你学习进度的了解，也是对我们设计的学习路径的反馈
> 目前设计的学习路径仍在改进中，需要借助各位同学学习后的反馈以进行后续优化，一个人的力量太过渺小，我们可以一同进步
> 如果有信心证明自己的能力已达到某阶段的考核要求，则可提交作品集后向考核负责人申请跳级面试，通过后直接从该阶段往后开始进行学习
> 学习内容中给出的任何条目都只是我们推荐的学习内容，并不代表这是你所需要学习，或所能够学习的全部内容。如果你有更好的技术选型，可以联系我们补充

本考核指南期望：参与考核的同学能在一整年内锻炼出可以对接就业的设计体系与能力。因此，主要的规划如下：

4. 帮助你明确 AI 在设计中所能发挥的作用和局限
5. 打下以平面设计为主的设计思维基础，同时保留向后兼容其他设计的自由度

## 考核说明

### 如何提交任务

建议先学习这篇文章相关的内容：[Git & Github](https://west2-online.feishu.cn/wiki/Lsz9w3CiGinXzgkevtmceHZknrf)

再按如下流程进行

- 创建一个 [Github](https://github.com) 账号
- 在个人 Github 账号，从 [collection-design](https://github.com/west2-online-reserve/collection-design) 仓库创建分支（fork）
- 克隆（clone）到个人电脑上
- 阅读本仓库的相关文档以及 collection-design 仓库的文件树结构（可借助 AI，但建议自行完成）以知晓怎样合理将自己的作业放在 collection-design 中
- 创建一次语义合适的提交（commit），对于怎样判断这是一个便于理解的提交，可查看[Conventional Commits specification](https://www.conventionalcommits.org/en/v1.0.0/)
- 从你的分支仓库，向 collection-design 的 main 分支发送一次推送请求（pull request），将本次包含你作业的提交推送到远端的仓库主分支
- 等待推送请求被合并到主分支，或联系考核负责人以通过推送请求
- 对于未按照以上流程完成的推送，我们将在评论中留下具体的打回原因，并等待你按流程重新发起的提交

如果你的提交被打回，请无需灰心，这**并不会对你的考核造成任何影响**，我们深知每个初学者面对这些未接触过的事物都需要熟悉

### 任务相关办法

在推送请求被合并后，考核负责人会联系你，协商时间，安排一次简短的面试

- 面试仅作为对你当前对考核任务的理解与完成情况的了解，并不会卡掉任何一个认真完成任务的同学
- 我们会在面试时或面试后给你一些后续发展的建议，愿我们聊的开心，我们也期望从你们身上学到新的知识

我们以**每一个任务结束的面试是否通过作为判断依据**，来决定我们是否接收考核者的下一个任务提交，还是等待你继续完善这个任务

任务后括号内的时间段仅供参考，并不作强制要求，请依据自身状态和时间安排自行决定

### 对 AI 的态度

我们永不反对 AI 的合理使用，包括：

- 检索公开素材、模板
- 总结与梳理需求
- 提供思路初稿
- 其他合理使用方式（待补充）

等对学习、设计与创作的辅助，我们在审核与面试时，仅会由于如下对 AI 不加思考的使用而**取消你的考核资格**：

- 不主动检查 AI 生成或寻找到的素材的版权许可
- 直接套用或 AI 修改后套用他人成品
- 存在版权问题或其他实在法律问题的使用方式（待补充）
