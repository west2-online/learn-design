# task2

> [!TIP]
> 你的个人品牌不应只住在自己的博客里：面试官可能在 Github 看到你的主页，同行可能在设计社区看到你的作品，同学可能在社交平台刷到你的内容。
> 每个平台都是一个展示橱窗，有着各自的尺寸、规则与受众。本阶段你要做的，是让这些橱窗传达出同一个“你”：
> 建立一套统一、可信、可识别的个人品牌视觉系统，并依据各平台的限制完成落地设计

## 学习

### 个人品牌视觉系统

> [!IMPORTANT]
> “统一”不等于“一模一样”。各平台的主页尺寸、内容规则与受众习惯差异巨大，机械复制同一张图只会处处违和。
> 你要建立的是可复用的视觉规则，而不是某一张固定的图，再依据每个平台的 Context 落地

1. 基础识别系统
    - Logo / 头像：简洁、可缩放（从 favicon 到头像大图都清晰）、深浅色背景下的可用性
    - 配色：主色、辅助色与中性色，说明色彩语义与使用边界
    - 字体：标题与正文字体选择，以及各平台字体受限时的回退策略
    - 图形语言：统一的分隔符、装饰图形、封面版式模板等可复用元素
    - 自我介绍：一句话定位与更完整的个人简介，各平台按长度与调性适配
2. 平台认知（Context）
    - 了解各平台的定位、内容规则、图片尺寸与受众习惯：
        - [GitHub](https://github.com/): 技术身份，主页 README 即个人门户，这部分可延续 `term1/task5` 改进，不再在作业中要求
        - [Behance](https://www.behance.net/) / [Dribbble](https://dribbble.com/) / [站酷](https://www.zcool.com.cn/): 设计作品社区，主页是作品的门面
        - [bilibili](https://www.bilibili.com/) / [小红书](https://www.xiaohongshu.com/) / [抖音](https://www.douyin.com/)等社交平台：内容消费场景，封面与简介决定第一印象
        - etc.
    - 建议为每个平台记录：头像尺寸、封面尺寸、简介字数限制、深浅色模式情况与链接能力
3. 跨平台一致性
    - 将个人 VI 规则 Token 化（延续 term1/task4 的 Design System 方法），让头像、配色、字体与图形语言在各平台稳定复现
    - 设计跨平台的统一视觉模板：封面版式模板、头图模板、卡片模板等
    - 说明哪些元素全平台统一、哪些允许因平台调整，以及原因

## 作业

1. 完成个人品牌视觉系统（VI）的设计：
    - 设计 Logo / 头像、配色、字体与图形语言，说明设计理由与风格取舍
    - 将规则 Token 化并集中展示（可在 Figma 中维护，并保留后续优化的空间）
    - 验证各元素在小尺寸（favicon / 列表缩略图）、大尺寸与深浅色背景下的可用性
    - 撰写不同长度的自我介绍（一句话、短简介、长简介），说明各平台的使用策略
2. 设计至少一个设计社区主页（Behance / Dribbble / 站酷等自选）：
    - 完成头像、封面、个人简介与作品封面等主页要素
    - 主页信息层级应引导访客快速了解你的方向并进入你的作品
    - 说明该平台的尺寸、规则等 Context 限制如何影响了你的设计
3. 设计至少一个社交平台主页（Bilibili / 小红书 / 即刻等自选）：
    - 完成头像、封面、简介、置顶内容等主页要素
    - 主页调性应与你的内容方向一致，并符合平台受众习惯
    - 说明与设计社区主页在信息层级与视觉侧重上的差异及原因
4. 跨平台一致性检查：
    - 用同一标准（如：他人 3 秒内能否认出这是同一个人）检查各平台主页的一致性
    - 记录各平台素材的尺寸、格式与导出方式，整理为可复用的模板
    - 检查各平台素材的字体、图片、图标授权，无法确认来源的不得发布
5. 提交内容：
    - 一份 README：涵盖个人品牌定位、VI 规则、各平台主页链接与设计说明、平台限制记录、素材导出方式与授权情况
    - 说明与 task1 博客之间的视觉衔接：两者应属于同一套个人品牌系统
