# task1

> [!TIP]
> 你已经在 `term1/task5` 中完成了个人博客，它是个人品牌可持续维护的“家”。但面试官可能先在 GitHub 看到你的技术身份，同行可能在设计社区看到你的作品，同学也可能在社交平台刷到你的内容。
> 本阶段要建立一套统一、可信、可识别的个人品牌视觉系统，并依据不同平台的 Context 分别落地。GitHub 主页不再是 term1 的小型 AI 作业，而是多平台个人主页中自由度最高的一处表达：它需要与博客互相连接，也要用真实项目和过程证据说明你是谁。

## 学习

### 个人品牌视觉系统

> [!IMPORTANT]
> “统一”不等于“一模一样”。各平台的版式能力、内容规则和受众习惯差异巨大，机械复制同一张图只会处处违和。
> 你要建立的是可复用的视觉规则与内容优先级，再依据每个平台的限制选择最合适的表达。

1. 定位与基础识别
    - 明确个人方向、希望被记住的能力与目标受众，并与 `term1/task5` 博客定位保持一致
    - Logo / 头像：简洁、可缩放，从 favicon、列表缩略图到头像大图都清晰，并检查深浅色背景
    - 配色：主色、辅助色与中性色，说明色彩语义、组合方式与使用边界
    - 字体：标题与正文字体选择，以及平台不支持自定义字体时的回退策略
    - 图形语言：建立分隔符、装饰图形、封面版式或卡片规则等可复用元素
    - 内容语气：准备一句话定位、短简介与长简介，让不同平台可以删减而不改变核心身份
2. 平台 Context
    - [GitHub](https://github.com/)：以 Profile README、Pinned Repository 和真实贡献组织技术身份，可以自由组合 Markdown、HTML、SVG、Action 或自部署动态内容，但必须考虑加载、维护和失败降级
    - [Behance](https://www.behance.net/) / [Dribbble](https://dribbble.com/) / [站酷](https://www.zcool.com.cn/)：以作品封面、案例顺序和简介建立设计可信度
    - [bilibili](https://www.bilibili.com/) / [小红书](https://www.xiaohongshu.com/) / [即刻](https://web.okjike.com/) 等社交平台：在快速浏览场景中用头像、封面、简介与置顶内容建立第一印象
    - 为每个平台记录头像 / 封面尺寸、简介字数、链接能力、深浅色表现、图片压缩与内容限制，不凭记忆套用尺寸
3. GitHub 主页设计
    - 先组织内容：一句话自我介绍、当前方向、代表项目或贡献、设计 / 技术能力、博客与作品集入口；只展示能够说明个人定位的信息
    - Profile README 是纵向阅读页面，不要把多个第三方 Stats、Badge 与技术栈图标堆成没有阅读顺序的卡片墙
    - 可以制作自定义 SVG、动态字体、艺术字、数据卡片或小型交互式项目作为高自由度表达，但装饰应服务于内容和个人 VI
    - 若使用 GitHub Stats 类服务，优先确认来源、部署方式、缓存、速率限制与失效降级；第三方服务不可用时，核心身份与链接仍应可读
    - 检查窄屏、深浅色、图片 Alt、文字对比与链接语义；不要只在自己的桌面浏览器和登录状态下验收
    - 明确原创、改造与引用边界；README 模板、代码、字体、图标、图片和动态服务均需记录来源与 License
4. 跨平台一致性
    - 将个人 VI 规则 Token 化（延续 term1/task4 与 term1/task5 的 Design System 方法），集中维护颜色、字体、图形和版式规则
    - 区分 Identity Token 与 Platform Mapping：前者保持身份稳定，后者记录同一规则如何适配不同尺寸、组件和内容优先级
    - 用统一标准检查各平台，例如他人能否在 3 秒内认出这是同一个人、是否能找到你的主方向与下一步入口
    - 与博客形成双向导航：平台主页能够进入博客 / 作品集，博客也能返回主要平台；避免多个入口信息互相矛盾

## 作业

1. 完成个人品牌视觉系统（VI）：
    - 明确个人定位、目标受众、核心能力与内容语气，说明它和 `term1/task5` 博客定位之间的继承或调整
    - 设计 Logo / 头像、配色、字体与图形语言，说明理由与风格取舍
    - 将规则 Token 化，区分跨平台保持不变的 Identity Token 与因平台调整的映射规则
    - 验证小尺寸、大尺寸、深浅色与单色场景；准备一句话、短简介和长简介
2. 设计并实际发布 GitHub 个人主页：
    - 完成 Profile README，至少清楚呈现自我介绍、当前方向、代表项目或贡献、能力证据，以及博客 / 作品集入口
    - 至少完成一个能体现个人 VI 与 GitHub 自由度的自定义模块，如自绘 SVG 标题、项目展示组件、可维护的数据卡片或与博客联动的内容模块
    - 可展示 `term1/task5` 中使用或制作的 Skill，但应说明它解决了什么真实问题，不把 Skill 名称或工具 Logo 当成能力本身
    - 说明 README 信息层级、平台限制、素材与动态服务的实现方式；检查窄屏、深浅色、未登录访问与第三方服务失效时的可读性
    - 不要求堆叠 Github Stats、技术栈 Badge 或装饰卡片；若使用，应自部署、理解维护方式，或明确第三方依赖与降级策略
3. 设计至少一个设计社区主页（Behance / Dribbble / 站酷等自选）：
    - 完成头像、封面、个人简介与作品封面等主页要素
    - 主页信息层级应引导访客快速了解你的方向并进入代表作品
    - 说明尺寸、规则和受众等 Context 如何影响内容顺序与视觉设计
4. 设计至少一个社交平台主页（Bilibili / 小红书 / 即刻等自选）：
    - 完成头像、封面、简介、置顶内容等主页要素
    - 主页调性应与内容方向一致，并符合平台受众的浏览习惯
    - 说明它与 GitHub、设计社区主页在信息层级与视觉侧重上的差异及原因
5. 完成跨平台一致性与真实访问检查：
    - 让未参与设计的人进行一次 3 秒识别与入口查找，记录他看到的身份、方向以及是否能找到博客 / 作品集
    - 检查各平台在未登录、窄屏和平台实际裁切后的显示；依据结果至少完成一轮修改
    - 记录全部素材的尺寸、格式、导出方式、来源与授权，整理可复用的平台映射模板
    - 检查博客、GitHub、设计社区与社交主页中的头像、简介、方向和链接是否一致，避免旧版本残留
6. 提交内容：
    - 可访问的 Figma 链接：第一个 Page 展示多平台最终预览，后续 Pages 至少保留 Final、Foundations、Components / Assets、References 与 Process；不提交独立预览图或设计导出目录
    - GitHub Profile 与已实际更新的平台主页链接；暂时无法发布的平台需说明限制，并提供按真实平台尺寸完成的 Figma 设计
    - README：个人品牌定位、VI 与 Token、平台 Context、GitHub 自定义模块、各平台设计说明、真实访问测试、修改记录、素材导出方式与授权清单
    - 说明与 `term1/task5` 博客的视觉和内容衔接，以及这些公开入口如何共同形成一条可继续扩展的个人品牌路线
